Maps

Report maps use the shared Plotly map helpers in util/figures.py — the exact make_map_with_aoi that Rivers Need Space uses. DGO polygons are colored by a class field and the AOI is outlined in red. Because the map is just a Plotly figure, it works in interactive HTML and in static SVG/PDF export with no extra work — add it with report.add_figure('map', fig) like any other figure.

AOI map (Plotly choropleth, like Rivers Need Space)

{% raw %}# figures.py — this is all it takes, exactly like rpt_rivers_need_space
from util.figures import make_map_with_aoi

def build_map(gdf, aoi_gdf):
    # gdf needs a geometry column named dgo_polygon_geom plus the columns
    # fcode_desc, ownership_desc and segment_area (metadata via define_fields)
    return make_map_with_aoi(gdf, aoi_gdf)

# main.py — maps are normal figures, so interactive & static/PDF both work
figures = {"map": make_map_with_aoi(gdf, aoi_gdf)}
for name, fig in figures.items():
    report.add_figure(name, fig){% endraw %}

Other shared map helpers: make_aoi_outline_map (fast fallback when the data is too large to embed) and make_point_map_with_aoi (point features). For Leaflet maps, the util.folium.riverscapes helpers apply the same brand defaults to folium.Map().

Grids: Side-by-Side Content

Pico's .grid puts its direct children next to each other in equal columns on screens ≥768px and stacks them below that. It is the default way to place two blocks side by side — figure next to text, table next to prose, card next to card — with no report-specific CSS.

Equal columns

Each direct child of .grid becomes one equal column (1fr each, so they always fill the content width). Columns are equal height — the shorter one stretches to match the longer one.

Grid children can be any block: paragraphs, lists, metric cards, tables or figures. This column holds a metric card:

Figure next to text

The typical "diagram next to explanation" layout: a figure in one column and its narrative in the other. The figure keeps its caption and report-figure styling inside the column.

Interactive mode embeds the live chart; static/PDF builds swap in the SVG automatically — the grid doesn't care which mode is being rendered.

Unequal columns (proportions)

Pico intentionally ships no column-width utilities: to make columns unequal, override grid-template-columns on the grid. Use an inline style for a one-off ratio or the shared .grid-2-1 / .grid-1-2 / .grid-3-1 classes in base.css. 2fr 1fr means the first column is twice the second.

A layout where the narrative takes 2fr and a compact table takes 1fr. The same markup works with any block children.

Add class="grid" plus a proportion class; the proportion class only changes the column template, it never breaks Pico's stacking below 768px.

{% raw %}<div class="grid grid-2-1">  <!-- or style="grid-template-columns: 2fr 1fr;" -->
  <div>…wider text column…</div>
  <figure class="report-figure">…</figure>
</div>{% endraw %}

Floats: Text Wrapping Around Figures

Pico has no float utilities, so base.css provides .float-left and .float-right. Add one to a <figure class="report-figure"> (or any block element) and the prose that follows flows around it instead of below it. Headings clear floats automatically; when the next block must start below the float, follow it with <div class="clearfix"></div>.

Figure floated right

Floated figures are sized at 42% of the content width by base.css, so the text has room to wrap. This paragraph and the next two are the body copy of the example: they flow up and around the right-floated figure, leaving a clean gutter on the figure's inner edge.

Note the caption comes along for the ride — it lives inside the <figure>, so it floats with the diagram instead of sliding underneath it. Floats work identically with tables, images and cards; nothing about them is figure-specific.

In print (PDF) the same float is kept at a bounded 40% width so WeasyPrint wraps the text the same way the browser does.

Table floated left

Floating left mirrors the pattern: the block hugs the left edge and the text wraps along its right side. Tables are a common float target in reports — a compact summary table can sit beside the paragraph that discusses it.

Only the outer block needs the class: everything inside it — the table, its header styling, the caption — behaves exactly as it would unfloated.

{% raw %}<figure class="report-figure float-right">
  {{ figures['ownership_pie'] | safe }}
  <figcaption>Figure 5: Ownership share.</figcaption>
</figure>
<p>…body copy that wraps around the float…</p>
<div class="clearfix"></div>{% endraw %}
